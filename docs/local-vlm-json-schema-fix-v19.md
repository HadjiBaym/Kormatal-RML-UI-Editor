# v19 — исправление запроса к локальному vision API

## Причина

Скриншот пользователя показывал HTTP 400: `response_format.type must be 'json_schema' or 'text'`. Код v18 посылал `response_format: { type: 'json_object' }`, который сервер LM Studio/локального совместимого API в этом окружении не принимает.

## Изменение

- Первичная попытка использует OpenAI-совместимый `response_format.type = json_schema` с именованной схемой `layout_analysis`.
- При HTTP 400, если тело указывает на несовместимость `response_format`/`json_schema`, клиент повторяет тот же multimodal-запрос с `response_format.type = text`.
- Текстовый ответ не принимается безусловно: существующая функция `extractJsonObject()` извлекает JSON, затем существующая нормализация проверяет элементы, размеры, цвета, координаты и типы.
- Для других HTTP 400 повторной попытки нет, чтобы не скрывать ошибки модели/запроса.
- Не менялись адреса, сетевые разрешения, мост, выбор модели или ограничения частных LAN IP.

## Проверка

Тестируется отправка image_url/data URL, выбор JSON Schema, автоматический fallback на text и разбор JSON-ответа. Эти mock-тесты не равны живому подключению к компьютеру пользователя; реальный ответ LM Studio нужно проверить из его сети.
