# Генератор интерфейсов по макету

## Что именно получается на выходе и когда результат считается готовым

Генератор выпускает два различных entrypoint-файла. Они решают разные задачи и не должны называться взаимозаменяемо:

- **`main.rml` — визуальный эталон.** Если импортирован PNG, он помещается в пакет как эталонное изображение без повторной отрисовки его отдельных частей; если импортирован SVG — файл растеризуется на разрешении холста после безопасной нормализации. Это сохраняет внешний вид источника настолько точно, насколько сохраняется сам источник и поддерживаемые SVG-эффекты, но графика в подложке не становится редактируемыми RML-объектами. Если источником был только JSON, автоматически созданная подложка синтетическая и не может считаться пиксельно-точной копией Figma.
- **`main-editable.rml` + `layout.rcss` + `layout.js` — редактируемая реконструкция.** Элементы становятся узлами RML с правилами RCSS. Для источников с полноценной координатной структурой она может быть близка к макету; при отсутствии координат, шрифтов, эффектов, текстовых глифов или исходного JS возможны отличия. Такой результат нельзя считать 100% эквивалентным без проверки в реальном VaCuus.
- **`layout.js` — поведение созданных контролов.** События элементов с явным типом `button`, `toggle` или `tab` отправляют `layout_ui_action`. Переключатели меняют локальное состояние для видимого feedback. Игровые действия (например, начать матч, открыть магазин, выйти из игры) должны быть связаны с Blueprint/C++-обработчиком в UE; универсальный генератор не знает контрактов конкретной игры и не выдумывает их.
- **`layout-manifest.json` и `layout-report.md` — доказательства проверки.** Манифест фиксирует выбранный entrypoint, происхождение PNG-эталона, число узлов, интерактивные зоны, проверенные внутренние ссылки и диагностические предупреждения. `nativeVaCuusRuntimeVerified` остаётся `false`, пока пакет не проверен рендером в целевой сборке UE/VaCuus.

### Критерии приёмки

Перед экспортом генератор проверяет, что обязательные файлы присутствуют, ссылки `href`/`src` разрешаются, JS подключён в `<head>`, PNG-эталон не пуст, а свойства RCSS известны матрице целевой версии и не относятся к неподдерживаемым/неотрисовываемым. Неизвестные или неподдерживаемые свойства — ошибка quality gate, а не тихая деградация. Ограниченные свойства создают предупреждения. Эти статические проверки не заменяют визуальную проверку runtime.

Для строгой приёмки рекомендуется сравнить скриншот `main.rml` и `main-editable.rml` в той же версии VaCuus, на том же разрешении и DPI scale. Пакет считается **визуально проверенным**, только когда есть screenshot/diff от фактического UE runtime, а **функционально проверенным**, только когда все интерактивные события подключены и пройдены. До этого отчёт не должен заявлять о 100% совпадении.

## Поддерживаемые входные форматы

- **SVG** — локальный разбор XML/SVG, группы и affine-трансформации, геометрия, основные заливки/обводки/текст. Сложные `path`/`polygon`/`filter`/маски растрируются в отдельные PNG при генерации, если браузер смог безопасно отобразить поддерево. Скрипты, `foreignObject`, обработчики событий и активные ссылки блокируются.
- **Figma JSON** — дерево слоёв с `absoluteBoundingBox`, заливками, текстовыми стилями, вложенными Frame/Component и Auto Layout. Используйте экспортёр из `figma-plugin/`. Figma Grid Layout не имеет прямого эквивалента в целевом Flexbox; такие слои получают явное предупреждение и требуют ручной переработки. Градиенты, image fills, некоторые эффекты и векторные контуры из JSON не восстанавливаются полностью; импортируйте визуальные слои как SVG для сохранения вида.
- **PNG/JPEG/WebP** — изображение сохраняется как эталон; при явно выбранной локальной vision-модели AI предлагает Layout IR, иначе открывается пустая сцена с размером эталона, куда слои добавляются вручную. Экспорт пустой сцены заблокирован до добавления хотя бы одного элемента. Геометрия и вложенность модели — оценка, а не исходный DOM.

## Как собирается RML UI: общий pipeline

Преобразование проходит через одну промежуточную модель `LayoutDocument` (Layout IR). Это важно: исходный формат не генерирует RML напрямую, поэтому узлы можно выбрать, переименовать, переместить, изменить размеры/цвет/текст и только потом создавать итоговые файлы.

1. **Извлечение из источника.** SVG: парсер читает `viewBox`, геометрию, `transform`, стили и текст. Figma JSON: считывает дерево Frame/Component, `absoluteBoundingBox`, текстовые стили и Auto Layout. PNG: хранит картинку как референс; vision-модель, если явно выбрана, только оценивает видимые элементы и координаты.
2. **Нормализация в Layout IR.** Каждый распознанный объект получает тип, координаты, габариты, заливку/обводку, текст и ссылку на родительский контейнер. Для SVG сложные path/маски/фильтры могут стать отдельными растровыми ассетами. Для Figma JSON вложенность и H/V Auto Layout переносятся в IR. Для PNG элементы — предположение модели или ручная разметка, а не восстановленный DOM.
3. **Генерация RML.** Контейнеры/фигуры сериализуются как элементы контейнера, текст — как отдельные текстовые узлы, а растровые слои — как изображения с относительными путями. Вложенные IR-узлы становятся вложенными RML-узлами.
4. **Генерация RCSS.** На каждый IR-узел создаётся селектор с шириной/высотой, цветом, шрифтом, границами и координатами. Flex применяется только там, где модель источника явно содержит раскладку (например, Figma Auto Layout или ручная настройка). SVG/PNG сами по себе не дают надёжной информации об Auto Layout, поэтому в остальных случаях используется позиционирование по координатам.
5. **Диагностика и проверка.** `layout-report.md` перечисляет формат, размеры холста, количество узлов по типу, шаги pipeline и ограничения. Откройте предпросмотр, проверьте низкую confidence у AI-узлов и исправьте предупреждения перед внедрением в UE5/VaCuus.

### Выбор AI-модели — необязательная настройка

По умолчанию **AI выключен**. SVG и Figma JSON разбираются детерминированно без модели; локальная vision-модель используется только для анализа PNG/JPEG/WebP. В окне генератора доступны варианты:

- **Без ИИ** — изображение служит подложкой; элементы добавляются вручную через кнопки «Панель», «Текст», «Фигура» и «Линия».
- **Qwen3-VL 2B** — локальная модель из `local-ai/`, ожидаемый alias `Qwen3VL-2B-Instruct-Q4_K_M`.
- **Другая локальная vision-модель** — введите alias модели, загруженной на локальном OpenAI-compatible сервере, и его адрес. Адрес может указывать на loopback (`localhost`, `127.0.0.1`, `::1`) или частный IPv4 локальной сети (`10.x.x.x`, `172.16–31.x.x`, `192.168.x.x`). Поддерживаются base URL вида `http://192.168.1.22:1234` и `http://192.168.1.22:1234/v1`. Публичные IP, доменные имена вне localhost и HTTPS не разрешаются.

Кнопка «Проверить подключение» вызывает локальный статус-маршрут и проверяет OpenAI-совместимый endpoint `/v1/models`; наличие `/health` не требуется (LM Studio его может не предоставлять). Идентификатор в selector должен совпадать с ID/alias, который сообщает локальный сервер. Выбранная модель и адрес сохраняются в `localStorage` браузера; API key не требуется. Если локальная модель остановлена, можно работать без ИИ — интерфейс не запускает загрузку модели самостоятельно.

### Контекст знаний для локальной vision-модели

При PNG-анализе сервер формирует ограниченный prompt context через `src/server/ai-knowledge-engine.ts`. Он включает постоянные инструкции не выдумывать UI и сохранять пустое пространство, релевантные записи реестров RML/RCSS и подходящие разделы Markdown из `docs/`. База знаний используется на каждой попытке JSON-ответа, включая повторы после некорректного/обрезанного JSON. В `Layout IR` diagnostics фиксируется число переданных записей, разделов документации и источники.

Это inference-time retrieval, а не fine-tuning. Для SVG и Figma JSON базовые геометрические данные по-прежнему извлекаются детерминированно — vision-модель не должна переопределять известные точные координаты исходного файла.

## Рекомендуемый рабочий процесс

1. Для наиболее точной структуры выберите один Frame в Figma, экспортируйте его через `figma-plugin/` и импортируйте JSON. Для векторного вида сложных графических слоёв экспортируйте дополнительно SVG.
2. Для макета без файла дизайна импортируйте PNG. AI-анализ необязателен и по умолчанию выключен: выберите локальную модель и запустите анализ либо выберите ручную реконструкцию — сцена будет создана по размерам изображения. Родители и раскладка, предложенные моделью, являются предположениями; их можно исправить в редакторе.
3. Проверьте иерархию элементов: укажите родительский контейнер, режим контейнера (`none`, horizontal или vertical), gap/padding, размеры и текстовые стили. Координаты в Layout IR локальные относительно контейнера; overlay предпросмотра показывает абсолютные координаты.
4. Сгенерируйте пакет экрана: `main.rml` (визуальный эталон), `reference.rcss`, `main-editable.rml` (редактируемая реконструкция), `layout.rcss`, `layout.js`, `vacuus-base.rcss`, `layout-report.md`, `layout-manifest.json` и `Assets/` для изображений. Проверьте quality gate и все предупреждения до внедрения в UE.
5. Сравните результат с источником в эмуляции VaCuus и затем подтвердите отрисовку в реальной версии VaCuus/RmlUi, установленной в UE 5.8.

## Локальный анализ PNG (без облачных AI API)

AI-анализ включается только по выбору пользователя. Для Qwen3-VL-2B-Instruct Q4_K_M можно использовать `llama.cpp` на `http://127.0.0.1:8081`; для другой vision-модели укажите её alias и адрес совместимого сервера: loopback или частный IP локальной сети. Маршруты `/local-ai/analyze` и `/local-ai/status` доступны приложению на этом компьютере; адрес назначения модели может быть loopback или RFC1918 частным IPv4 в локальной сети. HTTPS, публичные адреса и сторонние домены отвергаются. Ключ API не нужен, сетевой вызов Gemini/OpenAI отсутствует. Изображение передаётся только на выбранный локальный endpoint.

### Первичная установка

1. На компьютере, где будет запускаться редактор, при наличии интернета выполните в PowerShell из корня проекта:
   `powershell -ExecutionPolicy Bypass -File .\local-ai\Install-Local-Model.ps1` (CPU, работает на большинстве ПК). Для NVIDIA с совместимыми CUDA 12.4 runtime можно выполнить `...Install-Local-Model.ps1 -Backend cuda12`.
2. Скрипт скачает CPU-сборку `llama.cpp`, языковую модель `Qwen3VL-2B-Instruct-Q4_K_M.gguf` (примерно 1,11 ГБ) и vision-проектор `mmproj-Qwen3VL-2B-Instruct-Q8_0.gguf` (примерно 445 МБ), затем проверит SHA-256 файлов. Общий размер модели — примерно 1,56 ГБ, не считая рантайма.
3. Установщик использует прямые HTTPS-файлы официального релиза llama.cpp b11711, без запросов к GitHub REST API. Запустите в отдельном окне PowerShell `powershell -ExecutionPolicy Bypass -File .\local-ai\Start-Local-AI.ps1` (CPU) или `...Start-Local-AI.ps1 -Backend cuda12` после CUDA-установки. Оставьте это окно открытым, пока используете анализ PNG.
4. Запустите редактор обычной командой dev-сервера и используйте «Распознать локальной моделью». После первичной загрузки модель не требует интернета и файлы макета никуда не отправляются.

**Важно об архиве:** большие бинарные веса модели намеренно не вложены в ZIP этого исходного пакета: среда, в которой собирался пакет, не имела доступа к загрузке больших файлов из Hugging Face. Установочный скрипт скачивает официальные файлы Qwen и проверяет их опубликованные SHA-256 перед запуском. Поэтому для полностью изолированной машины веса нужно один раз загрузить на другой машине и перенести всю папку `local-ai/models/` вместе с `local-ai/runtime/` на носителе. До этого этапа локальный анализ PNG не заработает. SVG и Figma JSON обрабатываются офлайн и без модели.

### Состав модели и лицензия

- Основная модель: [Qwen3-VL-2B-Instruct-GGUF](https://huggingface.co/Qwen/Qwen3-VL-2B-Instruct-GGUF), файл `Qwen3VL-2B-Instruct-Q4_K_M.gguf`, SHA-256 `089d75c52f4b7ffc56ba998ffc50aae89fcafc755f9e7208aacca281dca6c2ae`.
- Vision-проектор: `mmproj-Qwen3VL-2B-Instruct-Q8_0.gguf`, SHA-256 `f9a68fabba69c3b81e153367b2c7521030b0fa8bb0de400c9599c8e6725f9c82`.
- В карточке GGUF-репозитория указана лицензия Apache-2.0. Сохраняйте атрибуцию и лицензионные тексты при распространении.
- Рантайм llama.cpp загружается из официальных релизов `ggml-org/llama.cpp`; бинарные релизы имеют отдельные условия и notices, приложенные к релизу.

Веса модели не включены в npm-зависимости и не загружаются автоматически при открытии редактора. Установка весов — единственный шаг, требующий первичного интернета; дальнейший inference выполняется локально.

## Единицы и RML/RCSS

Геометрия SVG/PNG/Figma переводится в CSS-pixel числа (одна единица источника сохраняется как один `px` при экспорте). Фактическое соотношение UE/Slate DPI/DP нужно калибровать в проекте; генератор не может знать DPI scale конкретного виджета. Используйте только свойства из `src/core/rcss-matrix.ts` и сверяйте результат с установленным VaCuus runtime. Генератор не обещает полную браузерную/RCSS эквивалентность.

## Проверки без Vite-сборки

```bash
node --experimental-strip-types --test src/core/tests/layout-generator.test.ts
node --experimental-strip-types scripts/sync-rcss-matrix.mts --check
```

Эти команды не запускают Vite build. Проверка `layout-generator.test.ts` охватывает парсинг SVG/Figma JSON, родительские связи, Auto Layout, генерацию RML/RCSS и SVG-превью.


### LM Studio по LAN

Для LM Studio на другом компьютере укажите, например, `http://192.168.1.22:1234/v1` (или адрес без `/v1`). В LM Studio загрузите vision-capable Qwen модель, включите Start Server и настройку **Serve on Local Network**. В противном случае сервер слушает только `127.0.0.1` и с другого компьютера не доступен. Убедитесь, что IP адрес принадлежит машине с LM Studio и локальный firewall разрешает TCP-порт 1234 только вашей LAN. Статус проверяется по `GET /v1/models`, а анализ — через `POST /v1/chat/completions`.


### Диагностика LM Studio по локальной сети

Если статус сообщает «Локальный движок не подтверждён», проверьте последовательно:

1. На компьютере с LM Studio откройте Developer → Server, загрузите именно vision-модель (Qwen-VL/Qwen2.5-VL/Qwen3-VL), нажмите Start Server и включите **Serve on Local Network**. По официальной документации LM Studio это переключает сервер с loopback на сетевой интерфейс.
2. На том компьютере откройте `http://127.0.0.1:1234/v1/models`. Должен вернуться JSON со списком моделей. Если не открывается — проверьте порт в LM Studio.
3. С компьютера, где работает редактор, проверьте `http://192.168.1.22:1234/v1/models`. Если локально на сервере работает, а здесь нет — проверьте IP компьютера, Wi-Fi/LAN и правило Windows Firewall для TCP 1234.
4. В конвертере выберите «Другая локальная vision-модель», задайте `http://192.168.1.22:1234/v1` (можно и без `/v1`), нажмите «Проверить подключение», затем выберите точный ID из `/v1/models`.

Редактор разрешает только loopback и RFC1918 частные IPv4 адреса. Не включайте проброс порта 1234 на роутере: подключение должно оставаться внутри доверенной LAN.


### Если конвертер открыт в удалённом preview (AI Studio)

Адрес `192.168.x.x` может быть правильным, но сервер приложения в удалённом preview находится не в вашей локальной сети. Обычный `/local-ai/status` выполняет запрос из процесса Vite, а не из браузера. В этом случае используйте локальный мост из `local-ai-bridge/Start-Local-Bridge.bat`: запустите его на компьютере, вставьте напечатанный токен в настройках генератора и выберите режим «Локальный мост». Мост слушает только `127.0.0.1`, а к модели обращается напрямую по LAN. Если браузер запрещает localhost/local-network fetch из удалённой страницы, запустите сам конвертер локально через `npm run dev`; это наиболее надёжный вариант.

Мост требует Node.js 22 или новее. Для LM Studio включите «Serve on Local Network», загрузите vision-модель и проверьте `http://192.168.1.22:1234/v1/models`. Не публикуйте порт модели в интернете.
