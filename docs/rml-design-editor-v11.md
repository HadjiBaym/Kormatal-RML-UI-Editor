# VaCuus UI Converter — RML Design Editor v11

## Root cause: unexpected UI elements during HTML/CSS conversion

Investigation reproduced an element duplication case with:

```css
.play::before { content: "★"; color: #fff; }
.play:hover::before { content: "★"; color: #0ff; }
```

The CSS converter materializes supported pseudo-elements as actual RML `<span>` nodes because RmlUi does not synthesize browser `::before`/`::after` content. Previously, the generated helper class hash included the target selector's dynamic pseudo-class. `.play` and `.play:hover` therefore got different helper classes, and the HTML-to-RML stage inserted two spans into the same button. That made the hover rule look like a second visible UI element.

## Fixes

- Generated pseudo spans carry a shared helper class with `display: none` in the base sheet, so state-only content is hidden until its rewritten selector matches. Source state rules have higher selector specificity and turn the span on when needed.
- Pseudo-element helper identity now removes supported dynamic/state pseudo-classes (`:hover`, `:active`, `:focus`, `:focus-visible`, `:disabled`, `:enabled`) before computing its stable class. Structural `:first-child`/`:last-child` constraints are checked against the HTML tree instead of being treated as interactive states. The generated RCSS keeps the original state selector, so multiple states style one helper node.
- Conflicting pseudo-element text content for the same target and position is not materialized as another span. A warning tells the user to use one content value or a real HTML element managed by the UI logic.
- Removed the permanent `Эмуляция VaCuus UE5` watermark from the preview iframe. It was generated by the editor, not by the imported HTML/RML.
- Changed `.vacuus-text-run` from `display: block` to `display: inline`. The generated span is retained where the converter needs an explicit text node, but ordinary mixed text no longer turns into separate block rows.

## Regression coverage

Tests verify that base and hover rules share exactly one RML helper span, different state content raises a diagnostic without duplicating the span, mixed-text helper style remains inline, and the preview iframe does not insert the watermark.

## Validation

- Node built-in test runner with TypeScript type stripping: 118 passed, 0 failed.
- RCSS catalog synchronization check: 103 properties in sync.
- TypeScript/TSX syntax transpilation was checked separately.
- Vite was not run. A full browser interaction test and native UE5/VaCuus render were not performed.
