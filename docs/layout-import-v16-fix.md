# Layout import fixes v16 — «Главный экран Play»

Дата проверки: 2026-10-18.

## Исправления в конвертере

1. SVG с Figma `foreignObject` больше не отклоняется только из-за этого элемента. Сначала выполняется проверка на `<script>`, inline event handlers и `javascript:` URLs; после этого неподдерживаемые `foreignObject` placeholders удаляются с диагностикой. Это не делает SVG с произвольным активным содержимым безопасным — активное содержимое по-прежнему отклоняется.
2. Извлечение ресурсов для PNG выполняется по ссылкам на реальные `defs`, а не копирует весь блок определений в каждый SVG-фрагмент. Это предотвращает повторение встроенных data URI и уменьшает объём промежуточного SVG.
3. Геометрия `<use>` восстанавливается по ссылочному узлу и его `x/y`/`transform`; используются связанные определения градиентов.
4. Группы с `clip-path` и составной графикой растеризуются как целый слой, чтобы не терять общую обрезку и порядок смешивания.
5. Для JSON-экспорта Kormatal/Figma to JSON Exporter добавлен отдельный адаптер. Когда координаты отсутствуют, генератор сообщает об эвристическом позиционировании и не заявляет точного восстановления.
6. Когда JSON и SVG импортированы вместе и JSON не содержит координат, рабочей геометрией становится SVG. JSON остаётся источником структуры/метаданных, но слои не сопоставляются автоматически без общих ID, чтобы не придумывать связь.

## Проверка фактических пользовательских файлов

- `Главный экран Play.svg`: 4,217,116 байт; корневой `viewBox` 1920 × 1085 px; 3 `foreignObject`; нет `script`, event handler и `javascript:` URL. После обработки: 23 узла Layout IR (5 фигур, 18 растровых слоёв), 17 диагностик. 18 растровых слоёв успешно сопоставлены с локальными файлами `Assets/vector-001.png` … `Assets/vector-018.png`.
- `--------------play-structure(1).json`: корректный JSON; метаданные указывают на Figma to JSON Exporter; 3 Frame в экспорте, 78 исходных элементов; после игнорирования служебного `SLICE` создано 76 узлов (23 контейнера, 36 фигур, 15 текстовых узлов, 2 линии), 7 диагностик.
- JSON: 1920 × 1080 px; координаты `x/y` и `absoluteBoundingBox` отсутствуют. Расположение в самостоятельном импорте приближённое и основано на размерах, порядке слоёв, группах и текстовых якорях.
- Размеры SVG/JSON различаются: 1920 × 1085 против 1920 × 1080. При совместном импорте генератор использует SVG как визуальную геометрию и сообщает о расхождении высоты в 5 px.
- SVG не содержит элементов `<text>`: видимые надписи экспортированы как path-контуры. По SVG нельзя автоматически восстановить их как редактируемые текстовые поля.
- Все 18 путей `src="Assets/vector-NNN.png"` в сгенерированном RML проверены относительно локальных PNG-файлов. Отсутствующих ресурсов нет.

## Визуальная sanity-проверка

Собран локальный smoke-композит из Layout IR и растровых слоёв. При сравнении с отрендеренной исходной SVG-картинкой одинакового размера 960 × 542 px средняя абсолютная разница RGB составила около 0.89 уровня яркости на канал; примерно 11.6% пикселей отличаются хотя бы в одном RGB-канале, преимущественно на границах/сглаживании. Это сравнение композиции в локальном smoke-preview, **не** снимок нативного RmlUi/VaCuus.

## Известные ограничения

- `foreignObject` (backdrop-filter blur) удаляется, потому что VaCuus/RmlUi не выполняет HTML внутри SVG. Остальная графика сохраняется, где это возможно.
- Path-надписи/иконки, фильтры и clipped composites растрируются в PNG и не редактируются как отдельные векторные/текстовые слои.
- JSON без координат не может дать пиксель-точное размещение; используйте сопутствующий SVG для верного внешнего вида.
- Полная Vite-сборка и нативный UE5.8/VaCuus runtime не запускались. Перед production проверяйте пути в `Content/DevUI`, `LogVaCuus` и скриншот целевого виджета.
